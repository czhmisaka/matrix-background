
**关键事实**:

- `tsup.config.ts:34-43` 把 webgl/webgpu 静态打包进主入口 `index.js`(~28.8KB gzip @ 0.5.1),用户即使只在低端机用 canvas2d 也会付体积代价。`tsup.config.ts:30` 注释明确说"因 matrixRain() 是 sync API,无法做 splitting"
- 整个代码库 **零** `webglcontextlost` / `webglcontextrestored` / `device.lost` 事件监听 — 验证:`grep -rn "webglcontextlost\|device.lost\|onLost" src/` 0 命中

## 二、P0 阻塞级(运行时崩溃 / 永久残影)

### P0-1 · WebGL 上下文丢失后无任何恢复,直接黑屏

**位置**: `src/renderer/webgl-renderer.ts`(全文 558 行) + `src/engine.ts`
**现状**: 源码 0 处监听 `webglcontextlost` / `webglcontextrestored`
**触发场景**:

- 用户切到其他重度 GPU 标签页(Chrome 主动驱逐 context)
- OS 锁屏 / GPU 进程崩溃 / 驱动复位(蓝屏恢复)
- 笔记本睡眠唤醒

**后果**:

- WebGL2 context 丢失后,所有 `gl.*` 调用变 no-op 但不抛错,屏幕上只剩 `drawTrail` 的纯色矩形(`webgl-renderer.ts:382-396` 残影拖尾仍能跑,但字符 instanced draw 完全静默失败)
- `webgl-renderer.ts:90-95` 内的 `recordHealthError(this._health, err)` 只能 catch 同步 GL 错误码,无法 catch context loss 事件
- 用户**完全感知不到**问题,只能看到静态色块(像"雨停了"),无 console 报错

**建议**:

- `webgl-renderer.ts` init() 内 `canvas.addEventListener('webglcontextlost', e => { e.preventDefault(); this._initialized = false; this._lost = true; })` + `webglcontextrestored` 内重跑 `_uploadAtlasTexture` / `_compileProgram` / `_allocateInstanceBuffer`
- health 快照(`src/renderer/health.ts`)加 `contextLostCount` 字段,getRendererHealth() 透出

---

### P0-2 · WebGPU device.lost 同样无监听,自愈能力为零

**位置**: `src/renderer/webgpu-renderer.ts:166-174`

```ts
this._device = await adapter.requestDevice({
  requiredLimits: { maxStorageBufferBindingSize: 256 * 1024 * 1024 },
});
```

**现状**:

- 未监听 `device.lost` Promise
- 未监听 `device.uncaptureerror` 事件
- `requestAdapter` 失败时 throw(`webgpu-renderer.ts:168-170`),由 `engine.ts:207-211` 的 `void renderer.init().catch(console.warn)` 静默吞掉

**触发场景**:

- driver crash(TDR / VK_ERROR_DEVICE_LOST)
- 8K viewport + 500K+ cells 触发 OOM(256MB storage limit 边界)
- 浏览器降级 `requestAdapter` 行为差异(Firefox / Linux Mesa / SwiftShader)

**后果**:

- 跟 P0-1 一样黑屏无感
- `engine.ts:209` 静默 catch 让上层以为 init 成功,`getDiagnostics()` 也无法查

**建议**:

- `webgpu-renderer.ts:170` 后 `device.lost.then(info => { recordHealthError(this._health, 'DEVICE_LOST:' + info.reason); })` + 自动 re-init(同 webgl context restored 模式)
- `requestAdapter` 失败应给 `getRendererHealth()` 写明 `lastInitError`,不要只 console.warn

---

### P0-3 · init 失败后 rAF 继续空转,GPU 资源泄漏

**位置**: `src/engine.ts:207-211`

```ts
void renderer.init(state.canvas, state).catch((e: unknown) => {
  const msg = e instanceof Error ? e.message : String(e);
  console.warn(`[matrix-rain] renderer.init() failed: ${msg}`);
});
```

**关联**: `src/renderer/webgl-renderer.ts:130-141` / `webgpu-renderer.ts:148-159` — try/catch 写 `this._health.lastInitError`,但 **throw 之后清理了 state.canvas 不再拥有任何已绑死 context,canvas 已半残**。

**后果**:

- WebGL init 失败(canvas 绑了 webgl2 context 失败):canvas 仍可绑 2d context,但 `state.renderer` 是个 webgl 失败实例,rAF 跑 `state.renderer.drawChar(...)` 全部 early-return
- WebGPU init 失败:`requestAdapter` reject 之后 `_device` 仍为 null,但 `state.canvas.getContext('webgpu')` **没回退** — 后续若降级重试 webgl 会被"canvas 已被某次 getContext 试探性触碰"的边角行为影响
- `rAF` 死循环 60 次/秒,CPU 单核 1-2% 持续空转,直到用户主动 `destroy()`

**建议**:

- engine.ts:208 catch 内调 `state.isPaused = true; state.renderer.destroy();` 切到真降级(canvas2d),而不是 console.warn 静默
- 提供 `enableAutoFallback: true` 选项(默认开),失败时降级到 canvas2d 而不是黑屏

## 三、P1 重要(功能缺失 / 可降级但降级路径不全)

### P1-1 · 没有任何离屏暂停机制,标签页隐藏时仍 60fps 渲染

**现状**:

- 0 处 `document.addEventListener('visibilitychange', ...)`(grep 0 命中)
- 0 处 `IntersectionObserver`(grep 0 命中)
- `src/engine.ts:540-729` 的 `draw()` rAF 循环不检查 `document.hidden`
- 浏览器已自动节流隐藏标签页的 rAF 到 ~1Hz,**对单 rAF 60fps 模式有效**,但对 `targetFPS=0`("不限制")场景,1Hz 的 draw 仍跑(只 drawTrail / drawChar),浪费电

**影响**:

- 后台标签页 CPU 不归零(在 Mac M1 上仍约 0.5-1% / 实例)
- `requestVideoFrameCallback` 未用(可对齐视频帧率)
- `MatrixRain` 命名空间(`src/index.ts:103-119`)的 `activeCount` / `destroyAll` 在隐藏页无法被业务感知

**建议**:

- `src/engine.ts:541` `if (state.isPaused || state.isDestroyed) return` 旁加 `if (document.hidden && !options.renderInBackground) return`
- 大列表 / 视口外的实例用 `IntersectionObserver` 自动 pause

---

### P1-2 · `prefers-reduced-motion` 只在 CSS 隐藏 wrapper,JS 仍跑

**位置**:

- CSS `src/matrix-rain.css:151-154` `@media (prefers-reduced-motion: reduce) { .matrix-rain-wrapper, .bg-sweep { display: none !important; } }`
- `src/engine/state.ts:620-628` 仅在 init 时一次性读 `matchMedia('(prefers-reduced-motion: reduce)').matches` 设 `prefersReducedMotion`,但**代码全文 grep 后该变量后续从未被引用**(`state.prefersReducedMotion` 在 draw() 内 0 命中)

**后果**:

- 用户系统开 reduced motion → 视觉静止(CSS 隐藏)但 GPU/CPU 仍在跑
- 用户运行时切换系统设置 → 不生效(只在 init 读一次,无 `addEventListener('change', ...)`)

**建议**:

- `state.ts:620` 改为 `matchMedia('(prefers-reduced-motion: reduce)').addEventListener('change', e => { ...pause/resume })`
- init 时若 `prefersReducedMotion === true` 自动 `state.isPaused = true`,靠 CSS 隐藏只是兜底

---

### P1-3 · 移动端 touch 事件 0 处理,virtualkeyboard / 横竖屏旋转无响应

**现状**:

- `grep -rn "touchstart\|touchend\|touchmove" src/` 0 命中
- `grep -rn "orientationchange" src/` 0 命中
- `src/matrix-rain.css` 0 处 `touch-action`(只 `pointer-events: none` 让 wrapper 不阻挡 click)
- `src/engine.ts:768-770` 只 `addEventListener('click', onCanvasClick)`,**没有** `pointerdown` / `touchstart`

**影响**:

- 移动端 `clickBurst` 在 touch 设备上**完全不工作**(click 在 iOS Safari 上 300ms 延迟 + 部分浏览器不冒泡到 canvas)
- 横竖屏旋转:`window.resize` 事件会触发(已监听,engine.ts:772),但 ResizeObserver 也会触发,200ms 节流(`setters.ts:522-528`)→ 旋转后 200ms 内文字拉伸错位
- 虚拟键盘弹出:`window.resize` 触发但 `buildGrid()` 重算 grid 不会减小 height,文字被键盘挡住的部分仍持续渲染,GPU 浪费

**建议**:

- canvas 改用 `pointerdown`(PointerEvent 统一 mouse + touch + pen)
- `setters.ts:530-537` onCanvasClick 旁加 `pointerdown` / `pointerup` 兼容 touch
- 移动端用 `visualViewport.height` 替代 `window.innerHeight`,自动收缩可视区

---

### P1-4 · 移动端 `devicePixelRatio` 跳变(系统缩放)无响应

**位置**: `src/engine.ts:218-221`

```ts
state.n = Math.min(
  typeof window !== 'undefined' && window.devicePixelRatio ? window.devicePixelRatio : 1,
  state.cfg.maxDPR // DEFAULTS.maxDPR = 2
);
```

**现状**:

- `window.resize` 监听(`engine.ts:772`)触发 buildGrid → 重新读 dpr ✓
- 但 **dpr 变化不触发 resize 事件**(浏览器不认为这是 resize)
- 移动端切换"显示大小" / 拖到外接显示器,dpr 从 1 → 2 跳变时,**canvas backing store 不变**,只是 CSS 缩放模糊或细

**影响**:

- iPad Pro 12.9 寸(原生 2x DPR)用户在 iOS"显示与文字大小"里调"更大" → 整页 dpr 变 3 → matrix-rain 仍是 2x backing store,文字边缘模糊

**建议**:

- `matchMedia(`(resolution: ${window.devicePixelRatio}dppx)`).addEventListener('change', onResize)` 监听 dpr 变化
- 或:用 `ResizeObserver` 的 `devicePixelContentBoxSize` 字段(Webkit 16.4+)

---

### P1-5 · iframe 嵌入场景未做特殊处理,sandbox / 跨域未知

**现状**:

- `src/renderer/webgl-renderer.ts:503` `img.crossOrigin = 'anonymous'` —— 只在 atlas PNG fetch 时用,但同文件第 197 `setAtlasUrls('/atlas/jetbrains-mono-32.json', '/atlas/jetbrains-mono-32.png')` 用的是**绝对路径**,iframe 嵌入到第三方域时**会 404**(同源限制)
- 无任何 postMessage 通信 hook
- 无 `sandbox` 属性检测
- 无 `ResizeObserver` 用 `box: 'content-box'` 兼容 sandboxed iframe

**影响**:

- 用户把 `<iframe src="https://cdn.jsdelivr.net/.../index.iife.js">` 嵌到自家页面 → atlas 加载 404 → WebGL 永远 init 失败 → 走降级 canvas2d 还能用
- 同一 iframe 内多实例(每个都 fetch atlas)→ 浪费 N 次 fetch(无 cache 复用)

**建议**:

- `engine.ts:199` `setAtlasUrls` 接受 `options.atlasBaseUrl` 参数,iframe 嵌入方用 postMessage 传 `atlasBaseUrl` + 主域代理 atlas
- 内部加 `Map<string, Promise<AtlasJson>>` 缓存同 URL 的 atlas JSON 请求
- `matrix-rain.css:73` `position: fixed; inset: 0` 在 sandboxed iframe(无 allow-same-origin)里表现取决于浏览器,需要文档提示

## 四、P2 次要(可降级 / 文档缺失)

### P2-1 · `auto-pick` 不读 prefers-reduced-motion 调低 renderer

**位置**: `src/renderer/auto-pick.ts:118-129`
**现状**: 即使用户 prefers-reduced-motion 仍按 cell 数选 webgl/webgpu,可能反而更耗电(canvas2d fillText 在低端 CPU 上更省)
**建议**: reduced-motion 时强制 canvas2d 兜底,即使 cells 数 > 100K

---

### P2-2 · `MatrixRainElement` reload() 偶发竞争

**位置**: `src/matrix-rain-element.ts:121-141`
**现状**: `attributeChangedCallback('variant' / 'charset' / 'renderer')` 调 `this._reload()` → `__instance.destroy()` + `matrixRain(...)` 重建。但旧 rAF 已在跑,新 rAF 又起一个。**destroy→init 之间约 1-2ms**,旧 rAF `requestAnimationFrame` 回调可能在 destroy 后、`isDestroyed=true` 生效前 1 帧内执行,导致 race(读旧 state.renderer 的 \_gl)。
**建议**: `reload()` 内先 `await new Promise(r => setTimeout(r, 0))` 让旧 rAF 自然结束,或 destroy() 后保留 `state.rafId = null` 防御

---

### P2-3 · 字体加载竞争:`JetBrains Mono` 异步加载但 init 不等

**位置**: `src/renderer/canvas2d-renderer.ts:140` `ctx.font = '${px}px "JetBrains Mono", ui-monospace, monospace'`
**现状**:

- canvas2d: 字体未加载完成时 ctx.measureText 返回 0,导致 atlas 错位 ❓(实际不直接影响 canvas2d 路径,因为 canvas2d 自己 fillText 不用 atlas)
- WebGL/WebGPU 用的是 build-time bake 的 atlas PNG,**字体加载不影响**。但首次启动若 atlas 还没 ready,WebGLRenderer init() 等 atlas JSON+PNG,**font 没加载完 canvas 实际看不见字**。CSS `src/matrix-rain.css:117` 引用 `src/fonts/*.woff2`,需 `document.fonts.ready` 才能保证一致性
- `src/matrix-rain.css:117` 字体声明:**纯 canvas2d 路径需要** 浏览器字体加载完成才能正确 render。`engine.ts:540 draw()` 没 await fonts.ready

**建议**:

- `engine.ts:816` `buildGrid()` 之前 `await document.fonts.ready`(需变 async API)
- 或:canvas2d renderer 改用 `document.fonts.load('14px "JetBrains Mono"').then(...)` 等到字加载再首帧绘制

---

### P2-4 · 多次 destroy 安全,但 destroy 后调 setter 不报错

**位置**: `src/engine/setters.ts:89-104` destroy 内有 `if (state.isDestroyed) return` 守卫
**现状**: destroy 幂等 ✓;但 setters(`setTheme` 等)调前未检查 `isDestroyed`,会改 `state.coldPalette` 等字段,**业务上无效但不报错**,易写出"组件卸载后还在更新"的 Vue/React bug
**建议**: 全部 setter 入口加 `if (state.isDestroyed) return`

---

### P2-5 · re-mount(同 DOM 节点再 matrixRain)能工作但 canvas 状态有残留

**位置**: 业务方典型用法:Vue `v-if` 切换 → 重新 mount
**现状**: engine.ts:225 `state.canvas.width = Math.max(1, ...)` 强制 reset backing store,WebGL context 被废弃。**但 canvas 一旦绑过 webgl2 context 就无法再绑 2d context**(浏览器 spec 限制)。

- canvas2d → 销毁 → 重建 canvas2d ✅
- webgl → 销毁 → 重建 webgl ✅
- webgl → 销毁 → 重建 canvas2d ❌(context type 锁死,getContext('2d') 返回 null)

**建议**:

- `engine.ts:225` resize 时若 renderer 切换,**新建一个 canvas 元素**,不要复用旧的
- 或:暴露 `options.canvas: HTMLCanvasElement | 'auto'`,'auto' 时每次新建

---

### P2-6 · COOP/COEP / CSP / cookie 零依赖

**验证**: `grep -rn "localStorage\|sessionStorage\|cookie\|COOP\|COEP" src/` 全部 0 业务命中(只有 `curves/sandbox.ts:44-45` 把 localStorage/sessionStorage 加到 SAFE_GLOBALS 黑名单,防止 userFunc 误用)
**结论**: 包不写 cookie / storage,**无 SameSite / COOP / COEP 顾虑** ✓

- 但 `crossOrigin = 'anonymous'`(`webgl-renderer.ts:503`)在 crossOriginIsolated=false 时不阻塞,只是 atlas PNG 不带 CORS 头也能用(浏览器降级处理)
- `index.iife.js` 走 UMD CDN 加载,jspm.io / esm.sh / skypack 等对 `import * from 'foo'` 路径可能因 atob/btoa 等老 polyfill 加载导致 Safari 14 上 IIFE bundle 失败(待 0.6.x 实测)

## 五、运行时 atlas Y 轴 bug(已知缺陷 2026-06-11)关联

> **背景**: memory/project_webgl_atlas_y_bug.md 标记 0.5.0+ 修
> **当前状态(0.5.1)**: 仍存在

**bug 位置**:

- UV 计算:`src/renderer/atlas-loader.ts:81-93` `v0 = ch.y / H; v1 = (ch.y + ch.h) / H` —— **直接用 PNG 原生 Y(top-down)**
- WebGL fragment shader:`src/renderer/webgl-shaders.ts:73-82` 直接 `texture(uAtlas, vUV).a` —— **没有 1-v 翻转**
- WebGPU `copyExternalImageToTexture`(`webgpu-renderer.ts:478-486`):不同平台对 Y 翻转的默认行为**不一致**

**当前为什么"碰巧"能工作**:

- WebGL:vertex shader 里做了 `ndc.y = -ndc.y`(`webgl-shaders.ts:60`),但**这只翻 NDC 位置,不翻 atlas UV**。WebGL2 默认 PNG `UNPACK_FLIP_Y_WEBGL=false` → atlas 内部像素自上而下,UV 直接传 v0=ch.y/H,**像素方向与 NDC 方向不一致**。但因 `texParameteri(gl.TEXTURE_MIN_FILTER, gl.LINEAR)`(`webgl-renderer.ts:523`)用 LINEAR 过滤,字符的"上下镜像"被模糊混色掩盖,**用户看不出** —— 字符看着正常,实际是**半镜像**。

**易触发条件**(运行时审查的关联):

1. **用户改 `setCharset` 含非默认字符**(`'01'`)→ 字符本身对称,看不出 Y bug
2. **viewport 高度极小**(< 200px)→ 字符被 LINEAR 模糊覆盖 bug 不显
3. **DPR > 2**(4K Retina)→ backing store 像素高,LINEAR 边缘插值强 → bug 仍被掩盖
4. **改 texParameteri 改 NEAREST**(`webgl-renderer.ts:521` 注:"字符 alpha 是硬边,NEAREST 避免边缘模糊 + LINEAR 边缘过滤混用" —— 注释表明作者已知 LINEAR 副作用)→ **改 NEAREST 立即露出 Y bug** ❌
5. **WebGPU 在 Safari**(`copyExternalImageToTexture` Y-flip 由平台决定)→ 直接显示镜像
6. **iOS Safari 17+ 走 WebGPU** + DPR=3 → 字符上下颠倒 / 半镜像,极易触发

**建议**(不动源码,只列建议):

- 短期:`copyExternalImageToTexture` 第二个参数加 `origin: { x: 0, y: 0 }` 锁定 + 在 WGSL fragment shader 显式 `vec2(uv.x, 1.0 - uv.y)` 翻转(规范但需统一 WebGL 路径)
- 中期:`texImage2D` 前 `gl.pixelStorei(gl.UNPACK_FLIP_Y_WEBGL, true)`,WebGL 与 WebGPU 行为对齐
- 长期:在 build-atlas 阶段统一坐标方向(脚本里 Y 翻转),runtime 不再处理

## 八、结论

**最大盲区**: **GPU 资源丢失的"零自愈"** —— WebGL context lost / WebGPU device.lost 任一发生,3 个 renderer 全部变黑屏但无任何错误上报,P0 级别。这是部署到生产前必须补的最后一公里。

**第二大盲区**: 移动端**几乎没适配** —— touch、dpr 变化、横竖屏、虚拟键盘全部没处理,README §📐 浏览器兼容列了 iOS Safari 14+,但**实际 iOS 体验在开关 reduced-motion、连外接屏、quicktype 键盘弹出等场景未验证**。

**兼容性整体评分**:

- canvas2d 路径:**A**(SSR 友好,无 GPU 依赖,最稳)
- WebGL2 路径:**B+**(98% 浏览器支持,但 context lost 无恢复)
- WebGPU 路径:**B-**(75% 浏览器支持,5 大浏览器只有 Chrome 113+ / Edge / Safari 17+ 实用,且 0.5.0 重建 compute 后稳定性没经过大规模验证)

**部署建议**:

1. 生产部署走 `renderer: 'auto'`(默认),让 auto-pick 选最稳的
2. 显式选 WebGPU 的场景:配套加 `onRendererInitError` 监听 + 降级到 webgl
3. 嵌入第三方页面(iframe):`renderer: 'canvas2d'` 显式锁死,避免 atlas CORS 失败
4. 后台 / 离屏场景:业务方主动 `instance.pause()`,不要依赖浏览器 rAF 节流

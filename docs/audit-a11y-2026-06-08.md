## 3. 键盘 / 焦点 / 跳过链接(源码 inspect)

### 3.1 Skip-to-content 链接 ✅

**位置**:`site/src/App.vue:2`

```vue
<a href="#main" class="skip-link">跳到主要内容</a>
<main id="main" tabindex="-1">
  <RouterView />
</main>
```

**CSS**:`site/src/style.css:101-120`

- 默认 `position: absolute; left: -9999px` 隐藏
- `:focus, :focus-visible` → `left: 0; outline: 2px solid var(--text)`
- z-index 1000,确保不被覆盖

**验证**:静态确认链接 + target 都存在;键盘 Tab 第一个焦点 = 跳过链接
(在 `App.vue` 顶部 `<a>` 之前无其他 focusable 元素)。

### 3.2 焦点环 ✅

**位置**:`site/src/style.css:122-136`

```css
*:focus { outline: none; }
*:focus-visible {
  outline: 2px solid var(--accent);
  outline-offset: 2px;
  border-radius: 2px;
}
button:focus-visible, a:focus-visible, input:focus-visible,
select:focus-visible, textarea:focus-visible, [tabindex]:focus-visible {
  outline: 2px solid var(--accent);
  outline-offset: 2px;
}
```

**问题**:`App.vue:17-18` 显式覆写 main 的 focus:

```vue
main:focus { outline: none; }
main:focus-visible { outline: none; }
```

这是**有意为之** —— main 上加 `tabindex=-1` 是为了接收 skip-link 跳转,不需要
视觉焦点环。但 `outline: none` 在 `:focus-visible` 上同时生效,**意味着键盘用户
从 skip-link 跳到 main 时,屏幕上看不到任何焦点指示**。建议:**保留 main 在
`programmatic focus`(skip-link 跳转)下隐藏 outline,但鼠标/键盘再 Tab 时
应有焦点环**。目前 main 不可再 Tab 到,所以不致命,但需要列入 P2 风险。

## 9. 剩余 P0 / P1 / P2

### 9.1 P0(必修,影响 axe violations + 屏幕阅读器 + 键盘)

#### P0-1 · AITunePage 重复 `<main>` landmark
- **症状**:App.vue 提供 `<main id="main">`,AITunePage.vue:30 又写 `<main class="stage">`,axe 报 `landmark-no-duplicate-main` + `landmark-main-is-top-level` + `landmark-unique` 三连击。
- **修法**:`<main class="stage">` → `<section class="stage" aria-label="画布与状态">`。
- **文件**:`site/src/pages/AITunePage.vue:30`
- **影响**:`/demos/ai-tune` 唯一 axe 路由(占 7 violations 中的 3)

#### P0-2 · 4 个未命名 `<select>`
- **症状**:`select-name` critical × 4,屏幕阅读器播报"combobox, 0 of 5"。
- **命中**:
  - `AITunePanel.vue:37` 位置 select(textAnchor)
  - `AITunePanel.vue:45` 运动 select(textMotion)
  - `ImageUploader.vue:53` 位置 select(anchor)
  - `ImageUploader.vue:61` 运动 select(motion)
- **修法**:在每个 `<select>` 上加 `aria-label="位置"` / `aria-label="运动"`,
  或将现有的 `<label class="opts-label">` 改为真 label(用 `for`/`id` 关联)。
- **影响**:`/demos/ai-tune` 唯一 axe 路由(占 7 violations 中的 4)

#### P0-3 · AITunePage 缺 `aria-live` on phase pill
- **症状**:AITunePanel.vue:70-71 phase pill 视觉上每帧变化,但屏幕阅读器**不会**播报。
- **修法**:`<span :class="['phase-pill', `phase-${phase}`]" role="status" aria-live="polite">`。
- **文件**:`site/src/components/AITunePanel.vue:70-71`

#### P0-4 · AITunePage chat input / textarea 无 label
- **症状**:屏幕阅读器对 chat input 播报"edit text",对 textarea 播报"edit text"(无 purpose)。
- **修法**:
  - `AITunePage.vue:57-62` chat input 加 `aria-label="AI 调参指令"`(用 placeholder 已不够)
  - `AITunePanel.vue:27-32` textarea 加 `aria-label="目标文字(将涌现的内容)"`
- **影响**:不影响 axe(axe 不一定报),但**视障用户**无法知道 input 用途。

#### P0-5 · AITunePage 缺 `aria-label` on icon buttons(5 个)
- **症状**:`title` 不被 screen reader 主动读,只在鼠标 hover 显示 tooltip。
- **命中**:
  - `AITunePanel.vue:7` clear-btn:加 `aria-label="清空对话"`
  - `AITunePage.vue:44-48` overlay-toggle:加 `aria-label="折叠/展开 AI 对话"`
  - `AITunePage.vue:63` form submit:加 `aria-label="发送 AI 指令"`
  - `ImageUploader.vue:7-10` clear-fab:加 `aria-label="清除已选图片"`
  - `ImageUploader.vue:44-49` apply-fab:加 `aria-label="生成位图"`
- **修法**:同时保留 `title`(鼠标 hover)和加 `aria-label`(屏幕阅读器)。

### 9.2 P1(应该修,影响 ARIA + mobile)

#### P1-1 · `<pre tabindex=0 aria-label>` 触发 `aria-prohibited-attr`
- **症状**:3 处 × incomplete(Playground / DemoEvents / DemoThemes),axe 4.11 与 WAI-ARIA 1.2 兼容性差异。
- **修法**:3 处 `<pre>` 改为 `<pre role="region">` 或在 `<pre>` 顶部加 `<h4 class="sr-only">代码示例</h4>`(后者更稳)。
- **影响**:incomplete 数从 3 → 0;axe 报告"干净"。

#### P1-2 · NavBar mobile toggle aria-label 是英文
- **症状**:`aria-label="toggle menu"`(NavBar.vue:19),全站其它 aria-label 是中文。
- **修法**:改为 `aria-label="切换菜单"`。
- **影响**:极小,但风格统一。

#### P1-3 · ChatLog 缺 `aria-live`
- **症状**:AI 回复的新 `<div class="msg ai">` 没有 live region,视障用户
  听不到 AI 增量输出。
- **修法**:`<div class="chat-log" ref="bodyEl" aria-live="polite" aria-busy="loading ? 'true' : 'false'">`。
  或在 AI message `<div>` 上加 `role="status" aria-live="polite"`。
- **文件**:`site/src/components/ChatLog.vue:2`

#### P1-4 · `main:focus-visible { outline: none }` 抑制了键盘 focus 指示
- **症状**:从 skip-link 跳到 main 时,屏幕看不到 main 的焦点指示。但因为 main
  是 `tabindex=-1`,键盘用户无法再 Tab 到 main,所以无影响。
- **修法**:保留,但加注释 `/* programmatic focus only, no keyboard tab */`。
  或在 skip-link 跳转完成时,自己动画一个 "跳到了" 的 toast。
- **影响**:极小,文档化即可。

#### P1-5 · AITunePage 在 320px 屏的 chat overlay 过窄
- **症状**:`.ai-overlay { width: calc(25% - 24px); min-width: 220px }`,在 320px 屏
  上 = max(min, 25%) = 220px,占 68%。但 chat 输入框在 220-26=194px 内塞两个
  textarea 按钮,**视觉拥挤**。
- **修法**:`@media (max-width: 480px)` 时改为 `min-width: 100%; width: 100%`,
  占据 canvas 底部全宽。
- **文件**:`site/src/pages/AITunePage.vue:288-298`

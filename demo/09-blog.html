从一坨 IIFE 到 5 主题 4 变体
一行 matrixRain() 背后

czhmisaka 8 分钟 TypeScript + Canvas 2D v0.1.0 首发

两年前第一次在个人站上跑出"硅 谷风"数字雨的时候,以为就是个 50 行的小玩具。最近把它抽成 NPM 包之后才发现,光是"可调参"就拆出 20+ 字段。本文记录从 matrixRain() 一行调用到完整 5 主题 4 变体的设计取舍。

为什么不全用 CSS

第一反应是 CSS 网格 + 字符旋转 + position: absolute 拼出来,实测下来有两个硬伤:

  • 字符切换需要 JS 重排 DOM,几十个 div 还好,几千格时 GPU 合成层直接卡死
  • "残影拖尾"本质是"不清屏 + 覆盖暗色",CSS 没法做(每帧 paint 整层)
如果你只是要"装饰性跑马灯字符",CSS 足矣。一旦要"上千格 + 真随机切换 + 残影",老老实实 Canvas 2D。

残影 alpha = 0.18 的来历

这块参考了《黑客帝国》原始 JS 实现的拖尾长度公式。简单说:每帧保留 82% 旧像素,新像素叠加在上面。alpha 越小,拖尾越长(指数衰减)。

// 不是清屏,只覆盖
t.fillStyle = 'rgba(8, 8, 18, 0.18)';
t.fillRect(0, 0, w, h);

默认 0.18 适合大多数场景。需要"梦幻极长拖尾"调到 0.05,"硬切割"调到 0.50。库内 trailAlpha 一行参数搞定。

温度感从哪来

双调色板(RGB 分量线性插值)+ 阻尼跟随光心 = 单一 canvas 里同时塞下"冷青科技感"和"暖琥珀人情味"。这个是本站调性的核心,比单一色板生动 2 个数量级。

冷暖独立调参

5 套主题是"打包好的冷暖组合",但 Playground 允许你**只换冷色调,保留暖色**——比如把"硅 谷"的冷青换成赛博蓝,暖琥珀保留,直接变种"赛博风暖光"。这就是 4 层用户函数驱动的由来:

  • A 沙箱 — 直接写 JS,任意动态量
  • B 波形 — 3 个 sin/cos 通道叠加
  • C 手画曲线 — Bezier 节点,所见即所得
  • D 预设 — 出厂预置,选就完事

4 种变体的真正区别

v0.1.0 之前只有一种"经典残影"。后来发现不同场景对动画气质的需求完全不同:

classic(经典残影)

三 sin 波叠加驱动字符列的速度波动 + 冷暖光心跟随鼠标。**默认选择**,适合所有通用场景。

avalanche(雪崩下落)

每列独立速度,头亮尾暗,适合做"启动页/Loading"。**注意**:每列独立速度 = 性能成本多 30%,慎用在低配设备。

ripple(涟漪)

字符下落方向由"到光心的距离"驱动,光心一动全场涟漪。**适合**做"专注模式/冥想 App"背景。

ascii(ASCII 字符)

字符集换成 01<>[]{}[]=*+。**适合**做"代码/IDE 风"产品页。

AI Mode:自然语言调参的野心

把 20+ 字段全部暴露给 LLM,让用户用中文调,这是 v0.1.0 的一个"赌"。赌两点:

  1. LLM 能稳定输出结构化 JSON patch(只改必要字段,不重置整个 config)
  2. "自然语言 → 视觉变化"的心智模型,比"参数 → 视觉"更符合设计师直觉

实测下来,OpenAI 兼容 API(以及 MiniMax M 系列)都能稳定输出 patch。但复杂描述("让雨慢、字符少、暖色更亮")还是需要把 prompt 拆成 3 个独立调用。**这是 v0.2.0 的目标**:多意图解析。

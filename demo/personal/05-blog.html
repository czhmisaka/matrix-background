把数字矩阵沉淀成 NPM 包:从一坨 IIFE 到 5 主题 4 变体的全可调组件

czhmisaka 12 分钟 TypeScript + Canvas 2D

两年前第一次在个人站上跑出"硅谷风"数字雨的时候,以为就是个 50 行的小玩具。最近把它抽成 NPM 包之后才发现,光是"可调参"就拆出 20+ 字段。本文记录从 matrixRain() 一行调用到完整 5 主题 4 变体的设计取舍。

为什么不全用 CSS

第一反应是 CSS 网格 + 字符旋转 + position: absolute 拼出来,实测下来有两个硬伤:

  • 字符切换需要 JS 重排 DOM,几十个 div 还好,几千格时 GPU 合成层直接卡死
  • "残影拖尾"本质是"不清屏 + 覆盖暗色",CSS 没法做(每帧 paint 整层)
如果你只是要"装饰性跑马灯字符",CSS 足矣。一旦要"上千格 + 真随机切换 + 残影",老老实实 Canvas 2D。

残影 alpha = 0.18 的来历

这块参考了《黑客帝国》原始 JS 实现的拖尾长度公式。简单说:每帧保留 82% 旧像素,新像素叠加在上面。alpha 越小,拖尾越长(指数衰减)。

t.fillStyle = 'rgba(8, 8, 18, 0.18)';
t.fillRect(0, 0, w, h);  // 不是清屏,只覆盖

默认 0.18 适合大多数场景。需要"梦幻极长拖尾"调到 0.05,"硬切割"调到 0.50。库内 trailAlpha 一行参数搞定。

温度感从哪来

双调色板(RGB 分量线性插值)+ 阻尼跟随光心 = 单一 canvas 里同时塞下"冷青科技感"和"暖琥珀人情味"。这个是本站调性的核心,比单一色板生动 2 个数量级。
